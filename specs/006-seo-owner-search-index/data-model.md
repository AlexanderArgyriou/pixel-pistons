# Data Model: Owner Name SEO & Full Post Indexing

This feature has no database or content-schema changes. The "entities" below are metadata/data-shape concepts introduced or extended as typed constants and structured-data objects, not persisted records.

## OwnerIdentity (new constant: `src/constants/seo.ts`)

Represents the canonical identity of the site owner, reused across all structured data and metadata emission points.

| Field | Type | Description |
|---|---|---|
| `name` | `string` | Canonical full name: `"Alexandros Argyriou"` |
| `alternateName` | `string[]` | Alternate name forms search engines should associate with `name`: `["Alex Argyriou", "Alexander Argyriou"]` |
| `sameAs` | `string[]` | Verifying external profile URLs (LinkedIn, GitHub) used to disambiguate the entity |
| `url` | `string` | Canonical site URL representing the person (site root) |

**Validation rules**:
- `name` MUST be non-empty and MUST match the canonical spelling already used in `experience.astro`/`education.astro` ("Alexandros Argyriou") to avoid contradicting existing indexed content.
- `alternateName` MUST contain exactly the two additional variants requested ("Alex Argyriou", "Alexander Argyriou"); `name` itself is not repeated in this array.
- `sameAs` MUST contain only `https://` URLs to existing, already-configured profiles (reuse the LinkedIn/GitHub URLs already present in `src/config.ts` `profileConfig.links` and `experience.astro`).

**Relationships**: Consumed by:
- `Layout.astro` → sitewide `Person`/`WebSite` JSON-LD (all pages)
- `[...slug].astro` → `BlogPosting.author` JSON-LD (every post page)
- `experience.astro`, `education.astro` → existing `Person` JSON-LD (`alternateName` field added)

## BlogPost (existing entity, no schema change — indexability attributes clarified)

Existing entity from `src/content/config.ts` (`posts` collection). No new fields added. Attributes relevant to this feature, all already present:

| Field | Type | Indexing relevance |
|---|---|---|
| `draft` | `boolean` (default `false`) | When `true` and `PROD`, excluded from `getSortedPosts()`/`getStaticPaths()` → never built → never in sitemap → never indexable. No change needed. |
| `published` | `date` | Used for `datePublished` in `BlogPosting` JSON-LD; unaffected by this feature. |
| `slug` | derived | Determines the canonical post URL used for the `<link rel="canonical">` tag and sitemap entry. |

**State transition (unchanged, documented for clarity)**:

```text
draft:true  --(author flips draft:false, PROD build)-->  published, built, sitemap-listed, indexable
published   --(author flips draft:true, PROD build)-->   removed from build output, drops out of sitemap on next deploy
```

## Sitemap (existing, no change)

Generated by `@astrojs/sitemap` from all statically built routes. No new fields; confirmed via research.md that it already includes 100% of published posts and none of the drafts.
